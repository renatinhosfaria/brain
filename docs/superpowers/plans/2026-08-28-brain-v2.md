# Brain V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Promover o PRD V2, ampliar o Brain para principals dinâmicos, resolver telefone WhatsApp com prova semântica de mapping, disponibilizar `conversation_phone` para workers e CEO, e atualizar os artefatos operacionais sem tocar no Hermes core.

**Architecture:** O Brain mantém autorização e resolução como autoridade única. Workers usam MCP com capability derivada de token, Task, Run e origem Kanban; o CEO usa um plugin externo versionado que captura `ContextVar` e chama uma rota privada localhost que revalida a sessão no `state.db`.

**Tech Stack:** Python 3.11+, `unittest`, SQLite read-only/WAL, MCP 2.0, Starlette/uvicorn, TOML, YAML, plugin nativo `register(ctx)` do Hermes e `urllib` da biblioteca padrão.

**Spec:** `docs/superpowers/specs/2026-08-28-brain-v2-design.md` e `PRD.md` V2.

## Global Constraints

- Trabalhar somente em `/root/brain` nesta sessão; instalação em `/root/.hermes` será apenas documentada.
- Nunca modificar `/usr/local/lib/hermes-agent`.
- O Brain deve continuar atendendo somente localhost (`127.0.0.1`, `localhost` ou `::1`).
- `state.db`, `kanban.db` e arquivos de mapping são somente leitura; não adicionar DDL, INSERT, UPDATE, DELETE, checkpoint ou migration.
- Nenhum argumento model-visible poderá escolher telefone, LID, `chat_id`, `session_id`, `session_key`, Task, Run, Profile, board ou caminho de arquivo.
- Principals usam digests SHA-256 hexadecimais de 64 caracteres e credenciais distintas.
- O principal `default` é o gateway CEO; `porteiro` e `cadastro` recebem apenas `conversation_phone`; `reno` e `famaagent` conservam `conversation_recent` e `conversation_search`.
- O resolver deve interpretar semanticamente `lid-mapping-{phone}.json` e `lid-mapping-{lid}_reverse.json`; nunca escolher um candidato arbitrariamente.
- O telefone retornado pelo Brain permanece em dígitos com código de país quando presente; normalização comercial continua fora do Brain.
- Indisponibilidade de mapping produz resultado público `{"status":"unavailable","reason":"phone_not_resolved"}`; códigos detalhados ficam somente na auditoria.
- Cada mudança de comportamento deve seguir TDD: escrever teste, executar e observar falha, implementar o mínimo, executar sucesso, refatorar mantendo verde.
- Toda tarefa termina com o comando de teste indicado e um commit específico.
